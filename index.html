Every game is secretly a graph

A graph is just dots (vertices) joined by lines (edges). That simple idea runs inside almost every game you play: how enemies find you, how levels are generated, how tournaments are scheduled and how online players get matched. This page shows where graph theory is used in real games, then lets you play six games built as graphs.

How an enemy finds you in a real game

Games made with Unity

Shortest path · A*

Unity is one of the most widely used game engines. Its manual says the navigation system puts a node on each piece of the navigation mesh and uses A* to find the shortest path between them. Every Unity game whose enemies walk around obstacles is solving this graph problem.

Source: Unity Manual, Navigation Areas and Costs ↗

Pac-Man (1980)

Maze graph · greedy choice

The maze's intersections are vertices and its corridors are edges. At each intersection a ghost picks the next tile closest, in a straight line, to its target. Blinky targets Pac-Man's own tile; Pinky aims four tiles ahead. This greedy rule is not a true shortest path, which is why ghosts sometimes take the long way round and why players could learn patterns to escape.

Source: Game Design Skills, Pac-Man pathfinding ↗

Where graph theory is used in real games

The industry problems behind games you already know.

Enemy and NPC pathfinding

Shortest paths

Game maps are stored as a graph of walkable points or regions. When an enemy chases you in an open-world or strategy game, it runs a shortest-path search such as Dijkstra's algorithm or A* on that graph.

Chess engines and game AI

Trees

Every position is a vertex and every move is an edge, so the game becomes a huge tree. Chess and tic-tac-toe programs search this tree a few moves deep to choose the best move.

Random maze and dungeon levels

Spanning trees

Games that build a fresh level every time often treat rooms as vertices and pick a random spanning tree (with Kruskal's or Prim's idea). That guarantees every room is reachable and there are no loops.

Online matchmaking

Matchings

Players waiting for a match are vertices, with an edge between players of similar skill and region. Pairing everyone fairly at once is a matching problem on that graph.

Tournaments and esports brackets

Complete graphs, binary trees

A league where every team plays every other team is a complete graph, and each round of fixtures is a perfect matching. A knockout bracket, as in cricket or tennis, is a binary tree with the champion at the root.

Quests, skills and story choices

Directed graphs

RPG skill trees, quest unlocks and branching dialogue are directed graphs. An arrow from A to B means "finish A before B", and designers check there are no cycles so every quest can be completed.

Unit 2 · Hamiltonian path

Chess knight

Squares are vertices and knight jumps are edges. A knight's tour, visiting every square exactly once, is a Hamiltonian path.

Unit 2 · Spanning trees

Maze game

Rooms are vertices and open passages are edges. A "perfect" maze, with exactly one route between any two rooms, is a spanning tree of the grid.

Unit 2 · Digraphs

Snakes & Ladders

Squares are vertices and moves are one-way edges. Ladders are shortcut edges, snakes go backwards, and the shortest path gives the fewest dice rolls to win.

Unit 2 · Rooted trees

Tic-tac-toe

Each board position is a vertex and each possible move is an edge to the next position. The whole game forms a rooted tree, with the empty board as the root.

Unit 3 · 1-factorization

League tournament

Teams are vertices and every pair must play, so the league is a complete graph K₄. Each round is a perfect matching, and the full schedule is a 1-factorization.

Unit 2 · Eulerian trails

One-stroke puzzle

"Draw the house without lifting your pen" is an Euler trail question. Exactly two corners have odd degree, so it works only if you start at one and finish at the other.

Unit 2 · Minimum spanning tree

City-building roads

Towns are vertices and possible roads are weighted edges. The cheapest way to connect every town is the minimum spanning tree: here 2 + 3 + 4 + 5 = 14.

Unit 2 · Paths in digraphs

Endless runner

Each lane position is a vertex and each step forward is an edge. A train deletes a vertex, and surviving means finding a path from start to finish.

What the demo shows

The model

Each square is a vertex. Two squares share an edge if the chosen piece can move between them. Five pieces give five different graphs on the same 64 vertices.

Degree and bipartite

A square's degree is its number of moves: 2 in a knight's corner, 8 in the centre. A knight always lands on the opposite colour, so its graph is bipartite.

Knight's tour

Warnsdorff's rule jumps to the square with the fewest onward moves. It finds a Hamiltonian path that visits all 64 squares once. Pairing steps 1–2, 3–4, … gives a perfect matching.

Non-planar

A planar bipartite graph has at most 2V − 4 edges. The knight graph has 168 > 124, so it cannot be drawn flat without crossings.

Track graph properties

3 × 20

What the demo shows

The model

Three lanes, twenty steps. Each free cell is a vertex. An edge is one step forward: stay in lane or switch one lane over. A train deletes its vertex and all its edges.

Counting runs

Runs into a cell = the sum of runs into the cells that lead to it. Working left to right gives the total number of survivable runs.

Must-pass vs cut-vertex

A must-pass point lies on every start-to-finish run. A cut-vertex disconnects the graph somewhere. Every must-pass point (other than the start) is a cut-vertex, but not every cut-vertex is a must-pass point.

Bipartite, non-planar

Edges always join step k to step k + 1, so even and odd steps form the two parts. The open track has E = 133 > 2V − 4 = 116, so it is non-planar.

Can it be drawn?

What the demo shows

The model

Each corner of the drawing is a vertex and each line is an edge. Drawing it in one stroke means walking along every edge exactly once: an Euler trail.

Why degrees decide

Every time the pen passes through a vertex it uses one edge in and one edge out. So every vertex except the start and end needs even degree.

Euler's theorem

A connected graph has an Euler circuit if 0 vertices have odd degree, and an Euler trail if exactly 2 do. With 4 or more odd vertices it is impossible.

Hierholzer's algorithm

"Show solution" walks until stuck, then splices in detours from earlier vertices. It finds a full trail in time proportional to the number of edges.

What the demo shows

The model

Each cell is a vertex joined to its four neighbours: a 10 × 10 grid graph. Keeping only edges between cells of the same colour splits it into connected components, found with BFS.

Region graph

Shrink each component to one vertex and join two regions if they touch. Your region starts top-left; each move merges it with neighbouring regions of the chosen colour.

A lower bound

The numbers in the graph view are BFS distances from your region. A move cuts each distance by at most 1, so the eccentricity is a lower bound on the moves left.

Greedy vs optimal

The hint picks the colour that absorbs the most cells right now. It is fast but not always optimal: finding the true minimum for Flood-It is NP-hard.

Two algorithms, one kind of answer

DFS backtracker

Walk to a random unvisited neighbour, knocking down the wall. When stuck, back up. Gives long, winding corridors.

Kruskal

Shuffle every wall. Remove it only if the rooms on each side are not yet connected (union-find). Gives many short dead ends.

Both produce a spanning tree of the 14 × 9 grid graph. Then BFS from the start finds the unique route to the exit.

Maze graph properties

14 × 9

What the demo shows

The model

Rooms are vertices and open passages are edges. Every possible wall is an edge of the grid graph; the maze keeps some of them.

Spanning tree

A perfect maze has every room reachable and no loops: a tree. A tree on V vertices always has V − 1 edges, here 126 − 1 = 125.

Every edge is a bridge

Remove any passage from a tree and it falls into two pieces, so every edge is a bridge. Dead ends are the leaves (degree 1).

BFS escape

Breadth-first search visits rooms in order of distance from the start. In a tree the shortest route is also the only simple route.

chess.py · Knight move graph
import networkx as nx

def knight_graph(n=8):
    """Vertices = squares. Edge = a knight can jump between them."""
    G = nx.Graph()
    jumps = [(1,2),(2,1),(-1,2),(-2,1),(1,-2),(2,-1),(-1,-2),(-2,-1)]
    for r in range(n):
        for c in range(n):
            for dr, dc in jumps:
                if 0 <= r+dr < n and 0 <= c+dc < n:
                    G.add_edge((r, c), (r+dr, c+dc))
    return G

G = knight_graph()
print(G.number_of_nodes(), G.number_of_edges())   # 64 168
print(nx.is_bipartite(G))                          # True
subway.py · Track digraph
def track_graph(length, trains):          # trains = set of (lane, step)
    """Vertices = free cells. Edge = one step forward, same or next lane."""
    G = nx.DiGraph()
    for s in range(length - 1):
        for lane in range(3):
            for d in (-1, 0, 1):          # switch left, stay, switch right
                a, b = (lane, s), (lane + d, s + 1)
                if 0 <= lane+d < 3 and a not in trains and b not in trains:
                    G.add_edge(a, b)
    return G

T = track_graph(20, {(0, 5), (2, 5)})
print(list(nx.articulation_points(T.to_undirected())))   # choke points
stroke.py · Euler trails
def one_stroke(G):
    """Euler's theorem: connected and 0 or 2 odd-degree vertices."""
    odd = [v for v in G if G.degree(v) % 2]
    if not nx.is_connected(G) or len(odd) not in (0, 2):
        return None
    return list(nx.eulerian_path(G))      # Hierholzer's algorithm

house = nx.Graph([(0,1),(1,3),(3,2),(2,0),(2,4),(4,3),(0,3),(1,2)])
print(one_stroke(house))                  # a valid stroke, v1 -> v2
print(one_stroke(nx.complete_graph(4)))   # None: 4 odd vertices
flood.py · Region graph
def flood_regions(board):
    """Same-colour regions = connected components of the grid graph."""
    n = len(board)
    grid = nx.grid_2d_graph(n, n)
    same = nx.Graph()
    same.add_nodes_from(grid)
    same.add_edges_from((a, b) for a, b in grid.edges
                        if board[a[0]][a[1]] == board[b[0]][b[1]])
    regions = list(nx.connected_components(same))
    where = {cell: k for k, reg in enumerate(regions) for cell in reg}
    R = nx.Graph()                        # region-adjacency graph
    R.add_edges_from((where[a], where[b]) for a, b in grid.edges
                     if where[a] != where[b])
    return regions, R, where

regions, R, where = flood_regions(board)
print(nx.eccentricity(R, where[(0, 0)]))  # lower bound on moves needed
ttt.py · Minimax
LINES = [(0,1,2),(3,4,5),(6,7,8),(0,3,6),(1,4,7),(2,5,8),(0,4,8),(2,4,6)]

def winner(b):
    for x, y, z in LINES:
        if b[x] != "." and b[x] == b[y] == b[z]:
            return b[x]
    return "draw" if "." not in b else None

def minimax(b, turn):
    """+1 if X wins with perfect play, 0 for a draw, -1 if O wins."""
    w = winner(b)
    if w:
        return {"X": 1, "O": -1, "draw": 0}[w]
    nxt = "O" if turn == "X" else "X"
    vals = [minimax(b[:i] + turn + b[i+1:], nxt)
            for i, c in enumerate(b) if c == "."]
    return max(vals) if turn == "X" else min(vals)

print(minimax("." * 9, "X"))              # 0: perfect play is a draw
